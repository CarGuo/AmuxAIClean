# 矩形图小项目可读性修复 · 2026-09-06

## 直接执行

用户指出普通分析页的小矩形只剩名称或空色块，无法辨认或判断占用。原实现只限制前
40 个单独项目，完全不考虑可用尺寸；View 又在高度不足时隐藏容量、宽度不足时隐藏
全部文字。原「其他」按钮只滚动到某个列表位置，没有精确展示其成员。

本次从展示数据与交互一起修复，保留当前视觉风格和原始容量语义：

- `StorageTreemapPresentation` 依据实际视口计算矩形，独立项目必须能同时显示名称和容量；
  不可读项目合并后重新检查布局，最多遍历 40 个独立候选。没有目录名或容量百分比特例。
- 归组仍保留真实合计面积，不抬高小文件面积。图外为该组保留数量、容量和「查看明细」
  操作；组的面积过小时仍可从这个正常尺寸按钮进入，不依赖悬停或命中几像素区域。
- 小矩形使用紧凑双行文案，图标只在大矩形出现，容量不会再独立隐藏。
- `StorageDirectoryProjection` 同时拥有归组成员和明细列表。选择「较小项目」后，左侧只
  显示这组已测量项目；全部成员可分页访问，也能返回全部。分页不改变图形或总容量。
- 窗口尺寸与明细范围进入后台 projection key。缩放、搜索、下钻、返回沿用原扫描证据，
  不重新扫描文件。异步结果仍必须匹配页面/session/revision，列表保留已有 Finder、
  下钻与安全删除入口；分组本身不会产生删除授权。
- 新文案由原 String Catalog 提供中英文。没有修改扫描规则、安全边界、工程配置或依赖。

参考 [DaisyDisk 的 smaller objects 说明](https://daisydiskapp.com/guide/2/en/UnderstandingSunburst/)
与 [GrandPerspective 的焦点详情](https://grandperspectiv.sourceforge.net/HelpDocumentation/ViewFocusPanel.html)
所体现的分组/详情联动方式，未复制竞品源码。

### 自动化与渲染证据

- 15 项聚焦测试通过：既有面积/不重叠/零与未知容量规则；用户截图式的悬殊分布；
  不可读项目归组后面积比例不变；240 个小项目的完整明细与分页；真实临时目录的
  明细切换、缩放、搜索、返回且扫描 session 不变；两种语言的离屏渲染。
- 多语言完整性检查通过。首次专项日志中的 3 个失败来自同一新增测试的错误前提：
  占用 97% 以上的大目录仍会使 4000 点窗口的余下区域窄于最小文本宽度。
  修正后保留全部原有断言，新增该尺寸下必须继续归组的检查，再在足够宽的视口下
  验证恢复独立显示和全部列表；没有改变面积或可读性需求。
- SwiftPM 的原始 xcstrings 不会自动产生供 SwiftUI Text 使用的 lproj；本轮使用 Xcode
  的 `xcstringstool compile` 在包的 build bundle 中生成当前中英文表后再渲染，避免把
  陈旧资源表或 raw key 截图当作界面证据。未改项目运行期本地化实现。
- AppUI 全量包测试通过（1431 个 XCTest 调度项与 11 个 Swift Testing 测试），目标
  Debug 构建通过，形成 C3 证据。其余 8 包没有本轮修改，上一轮安全修复的全包结果
  仍单独记录，不表述为本轮重新运行。
