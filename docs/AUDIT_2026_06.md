## 一、核心结论（TL;DR）

1. **Tree 卡顿没修透**：v1.5.4 重构修对了"扁平化数据结构"，没修"扁平化的触发器"。`treeRevision` 仍被 `publishSnapshot` 每 0.4s 顶起来，叠加每行 body 内 `safety.evaluate` 同步调用 + LazyVStack 不复用 cell，3 层放大下 5 万节点必卡。
2. **架构层有"上游写放大 / 下游对抗"的味道**：`ScanCoordinator` 是 13+ `@Published` 字段的 God Object，下游用 cache + revision + staging 反复对抗"上游不该发的通知"。
3. **功能广度落后**：相比 Pearcleaner / Mole，缺 Sentinel、Lipo、UndoHistory、CACHEDIR.TAG 协议、AI Agent 多版本清理、Homebrew 主动 cleanup、FileSearch 等差异化功能。
4. **隐藏的静默失败**：`try?` 在 LaunchAgentScanner / AppUninstaller 等高频路径上 30+ 处违反项目规约（[CONTRIBUTING.md L57](file:///Users/guoshuyu/workspace/GSYCleanMac/CONTRIBUTING.md#L57-L57) / [SECURITY.md L125](file:///Users/guoshuyu/workspace/GSYCleanMac/SECURITY.md#L125-L125)），用户看到的"卸载残留 0 字节"可能是"扫不动"而非"真没残留"。
